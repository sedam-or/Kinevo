# 09 — Design system

Depends on: `08-frontend.md`. Prefix: `DS`. Reference direction (owner): **tactile + editorial grid/layout**.
Component states and copy: `standards/ux-states.md`. Tokens are the contract between design and code; code never hard-codes a colour, size, radius or duration.

## 1. Direction

| Principle | Meaning in practice |
|---|---|
| **Editorial** | Strong typographic hierarchy: a serif display face for page titles and big numerals, a clean sans for UI. Numbered section labels ("01 Today"), hairline rules, captions, generous margins, asymmetric two-column layouts (main + aside) on wide screens. Information is *set*, like a page, not scattered in cards. |
| **Tactile** | Controls feel like objects: layered ink-tinted shadows, a visible "edge" under buttons, a pressed state that moves 1 px and flattens the shadow, paper-like warm neutrals. Never glossy, never glassy, no gradients as decoration. |
| **Calm** | One accent colour used sparingly for the single primary action and for "now". Status uses colour **plus** icon **plus** text. |
| **Honest** | Facts, not gamification: no streaks, confetti or scores. Empty and error states explain and offer a next step. |
| **Accessible first** | Contrast values below are computed, not claimed (`scripts/contrast.py`); WCAG 2.2 AA is the floor. |

## 2. Layout and grid

| Token | Value |
|---|---|
| Breakpoints | `sm` 480, `md` 768, `lg` 1024, `xl` 1280 (min-width, mobile-first) |
| Content max width | 1200 px; reading width (notes, long text) 68ch |
| Grid | 12 columns ≥ `lg`, 8 columns at `md`, 4 columns below; gutter 24 px (≥ `md`), 16 px (below); page margin 16 / 24 / 48 px |
| Spacing scale (4 px base) | 0, 4, 8, 12, 16, 24, 32, 48, 64, 96 |
| Baseline | 4 px; line heights are multiples of 4 |
| Radius | 4 (inputs, chips), 8 (buttons, cards), 12 (dialogs/sheets) |
| Touch/click target | primary controls ≥ 44 × 44 css px (Android ≥ 48 dp); minimum anywhere 24 × 24 (WCAG 2.5.8) |

Page anatomy (≥ `lg`): left rail 72 px (icons + labels on hover/focus) → main column (8 of 12) with an editorial header (section number, title in display serif, one-line standfirst) → aside (4 of 12) for context (next up, review banner, links). Below `md` the aside stacks under the main column; the rail becomes the bottom bar (`08-frontend.md` §3).

## 3. Colour

Colours are defined in **OKLCH** (perceptual) with an sRGB hex fallback for browsers without `oklch()`. All colours are inside the sRGB gamut (checked). Contrast ratios below are WCAG 2.x relative-luminance ratios computed by `scripts/contrast.py`; **text ≥ 4.5:1, graphics and focus indicators ≥ 3:1**. Re-run the script after any token change; CI fails on any failure (TST-10).

### Semantic usage

| Token | Use |
|---|---|
| `paper` | page background |
| `surface` | cards, dialogs, popovers |
| `sunken` | inputs, wells, code blocks |
| `ink` / `ink-muted` / `ink-subtle` | primary / secondary / tertiary text (all ≥ 4.5:1 on `paper`) |
| `rule` | hairlines and decorative borders (not required to meet 3:1; never the only indicator of a control boundary) |
| `rule-strong` | control borders (inputs, checkboxes) — ≥ 3:1 on `paper` |
| `accent` / `accent-ink` | primary action background / its text; also "now" highlights |
| `accent-subtle` | selected row, "now" card tint (text on it is `ink`) |
| `success`, `warning`, `danger`, `info` | status text and icons on `paper`/`surface` (≥ 4.5:1); backgrounds use the 10 % tint with `ink` text |
| `focus-ring` | 2 px outline with 2 px offset, always visible, never removed |

Themes: `prefers-color-scheme` is honoured; the user can override in Settings (Auto / Light / Dark), stored in `localStorage` as a per-device convenience (the page renders correctly without it). `color-scheme` is set on `:root` so native controls follow.

## 4. Typography

| Role | Family (self-hosted, SIL OFL) | Use |
|---|---|---|
| Display | **Fraunces** (variable: weight, optical size) | page titles, big numerals (counts, timer), empty-state headlines |
| UI / text | **Inter** (variable) | everything else |
| Mono | **JetBrains Mono** | code blocks, ids, shortcuts |

Fonts are subset to Latin + Latin Extended (English and Indonesian), served from the app origin, `font-display: swap`, preloaded for the two faces used above the fold. Provenance entries are required in `brand/ASSETS.md` before use (Phase 5).

| Step | Size / line height (px) | Typical use |
|---|---|---|
| `text-xs` | 12 / 16 | captions, badges (never for essential information alone) |
| `text-sm` | 14 / 20 | secondary UI, table cells |
| `text-base` | 16 / 24 | body, inputs (prevents mobile zoom) |
| `text-lg` | 18 / 28 | lead text |
| `title-3` | 20 / 28 | card titles |
| `title-2` | 24 / 32 | section titles |
| `title-1` | 32 / 40 (display serif) | page titles |
| `display` | 44 / 48 → 64 / 64 ≥ `lg` (display serif) | Today "now" task, large counts |

Rules: body ≥ 16 px; numerals in times, durations and counts use `font-variant-numeric: tabular-nums`; line length ≤ 75 characters for prose; no text smaller than 12 px; user font-size scaling up to 200 % must not clip or overlap (rem units everywhere).

## 5. Elevation, edges and states (the "tactile" tokens)

| Token | Definition (light; dark uses `ink`-tinted darker shadows with lower alpha) |
|---|---|
| `shadow-rest` | `0 1px 0 var(--rule), 0 1px 3px oklch(0.24 0.02 60 / 0.10)` |
| `shadow-raised` | `0 1px 0 var(--rule), 0 4px 12px oklch(0.24 0.02 60 / 0.12)` |
| `shadow-overlay` | `0 8px 32px oklch(0.24 0.02 60 / 0.20)` |
| `edge-primary` | `0 2px 0 oklch(0.40 0.17 33)` — the visible lower "edge" of a primary button |
| `pressed` | `transform: translateY(1px); box-shadow: none` (+ `edge` reduced to 1 px) |
| `inset-field` | `inset 0 1px 2px oklch(0.24 0.02 60 / 0.12)` on `sunken` inputs |

Interactive states for every control: **default · hover · focus-visible · pressed · disabled · loading · error · (selected)**. Hover never carries meaning alone (touch has none). Disabled controls keep readable contrast (≥ 3:1 for the label) and explain why when focused/hovered (tooltip or helper text).

## 6. Motion

| Token | Value |
|---|---|
| `motion-fast` / `-base` / `-slow` | 120 ms / 200 ms / 320 ms |
| easing | standard `cubic-bezier(0.2, 0, 0, 1)`; exits `cubic-bezier(0.4, 0, 1, 1)` |
| Allowed | fade, small translate (≤ 8 px), height/opacity reveal, button press |
| Forbidden | parallax, auto-playing loops, bouncing, anything that moves the layout after load without user action |
| `prefers-reduced-motion: reduce` | all transforms removed; fades ≤ 120 ms; skeleton shimmer replaced by static placeholders; no animated progress other than value changes |
| Live timers | the visible seconds update does not animate and is not announced every second (§8) |

## 7. Component catalogue

All interactive primitives are built on **React Aria Components** (behaviour, keyboard, ARIA) styled with tokens; components contain no business logic (CA-15). Each component ships with a test for its states and an axe check.

| Component | Variants / states | Key requirements |
|---|---|---|
| Button | primary, secondary, quiet, danger · all states of §5 · loading (spinner + label retained, `aria-busy`) | min target 44 px; one primary per view region; icon-only buttons need `aria-label` |
| IconButton, Link | | link text is descriptive; external links show an icon and open in a new tab only when the user opts in |
| TextField, TextArea, NumberField | label always visible (no placeholder-as-label), helper text, error text linked by `aria-describedby`, character counter when a limit applies | error shown with icon + text, never colour alone; `autocomplete` tokens set (e.g. `current-password`, `new-password`, `one-time-code`) |
| Select, ComboBox, ListBox | single/multi | type-ahead, `Esc` closes, selected value announced |
| Switch, Checkbox, RadioGroup | | 24 px visual, 44 px hit area; module toggles use Switch with a visible state label ("On"/"Off") |
| DatePicker, TimeField | | typed entry always possible; locale-aware order; calendar popover optional |
| Dialog / Sheet | modal, non-dismissible while saving | focus trap, restore focus, `Esc` closes unless destructive-in-progress, labelled and described |
| Popover, Tooltip, Menu | | tooltip content also available without hover; menu typeahead and arrow keys |
| Tabs | | arrow-key navigation, roving tabindex |
| Toast (live region) | success, info, error · action optional · auto-dismiss ≥ 6 s, **paused on hover/focus**, error toasts persist until dismissed | `role="status"` / `role="alert"` for errors; never the only place an error is shown |
| Banner | info, warning, danger, success | persistent, dismissible only if non-critical |
| Card, Section | | headings in order; no card-in-card nesting beyond one level |
| Badge, StatusPill | task/draft/session states | icon + text; colour from status tokens |
| ProgressBar | determinate | labelled value `aria-valuenow`; never colour-only |
| Table / List rows | | real table semantics for tabular data; sortable headers are buttons |
| EmptyState | | headline (display serif), one sentence, one primary action, optional secondary link |
| Skeleton | | static under reduced motion; `aria-hidden` |
| CommandPalette | | `Cmd/Ctrl+K`; combobox pattern; results announced |
| TimelineItem, NowCard, Timer, DraftDiffRow, ConflictCard, ReviewBanner | domain composites | composed from the primitives; Timer follows §8 |

Moving items (milestone order, assignment time) always have **non-drag alternatives** (Move up/down buttons, or edit time fields): there is no drag-and-drop interaction in 1.0, and any future drag interaction must provide a single-pointer alternative (WCAG 2.5.7).

## 8. Accessibility requirements (WCAG 2.2 AA mapping) — `DS-A11Y`

| ID | Requirement | Verification |

| DS-A11Y-05 | Accessible authentication (3.3.8): no cognitive tests; paste into password fields allowed; password managers supported (`autocomplete`); TOTP field `autocomplete="one-time-code"` | E2E |
| DS-A11Y-06 | Redundant entry (3.3.7): the setup wizard and multi-step forms never ask for the same information twice in one process | review |

| DS-A11Y-08 | Reflow: no horizontal scroll at 320 px width and 400 % zoom (1.4.10), except the week schedule grid which offers a list view alternative; text spacing overrides do not break layout (1.4.12) | Playwright viewport tests |
| DS-A11Y-09 | Status messages (4.1.3): toasts/banners/save indicators use live regions; the running timer announces only on start, pause/resume (n/a), complete, and every 5 minutes if the user enables "announce progress"; seconds are `aria-hidden` | screen-reader script (NVDA + Firefox, VoiceOver + Safari, TalkBack) |

## 9. Terminology and localisation

User-facing nouns come from message keys so templates can rename them (`05-templates-and-setup.md` term registry). Copy rules: sentence case; verbs for actions ("Start", "Complete", "Apply schedule"); errors say what happened, why if known, and what to do; no blame ("You must…"), no exclamation marks, no humour in errors; numbers and dates via `Intl`. Indonesian is written natural-formal (kamu/Anda not mixed: use "kamu" in product copy by default `[ASSUMED]`, confirm with the localisation reviewer).

## 10. Token source and build

Until the web scaffold exists, the palette in `scripts/contrast.py` and this document are the source. From milestone M1, `web/src/styles/tokens.json` (W3C Design Tokens format) is the single source; a build script generates `tokens.css` (CSS custom properties with `oklch()` and hex fallback via `@supports`) and the TypeScript token types; `scripts/contrast.py` is updated to read the JSON. Changing a token requires re-running the contrast check and updating this document's tables in the same change.

## 11. Assets

Icons: **Lucide** (ISC licence) as inline SVG components, `aria-hidden` unless the icon carries meaning. No raster illustrations in the product UI in 1.0. Brand logos and banners: Phase 5 (`brand/`).
