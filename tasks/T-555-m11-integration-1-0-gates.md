# T-555: M11 integration: assemble the 1.0 gate evidence and report honestly

## Goal

One run executes every automated gate on a clean checkout and produces an evidence report that separates what passed, what was not run, and what only a human or an external party can do.

## Context

> **1.0 release gates** (`spec/13-roadmap.md` §3): Functional (J0–J9 pass in CI on Chromium, Firefox, WebKit; J9 on an emulator); Specification (`spec_tool.py check` clean, traceability exceptions justified); Security (all SEC-AC tests green, external review M-SEC or documented absence, no critical/high advisories); Accessibility (TST-11 green + manual audit DS-A11Y-16 recorded); Operations (restore drill and upgrade tests green, runbooks reviewed, image signed with SBOM/provenance); Privacy (PRV-01…09 satisfied, cloud documents counsel-reviewed); Validation (V1–V4 executed with recorded results); Legal/provenance (ledger complete, assets have rows, D-23 resolved).
> **This task runs the automatable gates** and writes `docs/release/1.0-gate-report.md` with one row per gate: `automated-pass`, `automated-fail`, `not-run (reason)`, `environment-limited (command, error)`, or `maintainer-action` (M-SEC, M-LEGAL, M-STORE, V1–V4, D-23, manual a11y audit, signing keys, branch protection). **It must never state that 1.0 is ready**; the report ends with the list of open maintainer actions. The privacy grep, `cargo deny check`, `cargo audit` (if installed), `pnpm audit --prod`, `python3 scripts/spec_tool.py check`, `python3 scripts/tasks_index.py --check`, `python3 scripts/check_sec_ac.py --strict`, `just legal`, `just a11y`, `just e2e` (all journeys), the module matrix (each toggleable module off), `just restore-drill`, `just upgrade-test --from-ref <previous milestone ref>`, `just bench` are run and their results transcribed with counts.
> **Rule**: integration tasks add no features. Defects are fixed in the owning task's files only when trivial (and noted), else raised as a blocking question for the architect.

## Scope

**In:**
- `docs/release/1.0-gate-report.md` generated by `scripts/gate_report.py` from command outputs saved in `dist/gate-logs/` (the script only formats; it does not decide pass/fail except from exit codes), the full journey run J0–J9, module matrix, and the Report.

**Out:**
- Declaring readiness, tagging a release, any maintainer action.

## Business rules

1. Nothing is reported as passing unless it was run; skipped items name the exact command not run and why.
2. The Report includes counts per command, environment-limited items and the SEC-AC table for all eight 1.0 gates.
3. A failing gate blocks the milestone and is listed under Questions with the failing test name.

## Security

- Re-run the privacy grep from AGENTS.md before declaring done and record the result.
- Run `cargo deny check` and `pnpm --dir web audit --prod`; record findings.

## Implementation notes

- Statuses are derived from recorded exit codes; a missing log is `not-run`.
- Maintainer-action rows are fixed text in the script and cannot be marked passed by the script.
