# T-002: Add Clock, IdGen, TokenGen, typed ids, Instant and TimeRange to the kernel

## Goal

The kernel offers injected time and id sources plus the canonical value types for ids, instants and half-open ranges. Every later crate uses these and never reads the wall clock or a random source directly.

## Context

> **ARCH-05** (`spec/02-architecture.md`): All time-dependent logic uses an injected `Clock`. No domain or application code calls a wall-clock function directly (CQ-07).
> **ARCH-25**: Ids are UUIDv7 generated by the application (`IdGen` port). Timestamps are `timestamptz` UTC.
> **D-17**: A "day" is a calendar day in the account's IANA timezone. All instants are stored as UTC `timestamptz`. All ranges are half-open `[start, end)`. Domain code receives an injected clock and never reads wall time.
> **SEC-23** (`spec/standards/security-by-design.md`): all tokens/ids from the OS CSPRNG via `rand_core::OsRng` behind the `IdGen`/`TokenGen` ports; tests inject deterministic generators.
> **CQ-06**: Ids, … instants, ranges … are distinct types with private fields and validating constructors (`TryFrom`/`parse`); invalid values are unrepresentable after construction.
> **CA-06**: `kinevo-kernel` has no async runtime, no sqlx, no axum, and compiles for `wasm32`.
> **Contracts** (`spec/standards/contracts.md` §1): Identifier = lower-case hyphenated UUID string. Instant = RFC 3339 UTC `YYYY-MM-DDTHH:MM:SS[.fff]Z`; input offsets accepted, output always `Z`, milliseconds only when non-zero. Validation kind `instant` (`spec/standards/validation.md` §2): year 1970–2100; fractional seconds ≤ 3 digits.

## Scope

**In:**
- `kinevo_kernel::time`: `Instant` newtype over `jiff::Timestamp` with millisecond precision, RFC 3339 parse (offsets accepted, converted to UTC, year 1970–2100, at most 3 fractional digits) and canonical formatting (`Z`, milliseconds only when non-zero). `serde` support uses the canonical form.
- `TimeRange { start, end }`: half-open, constructor rejects `end <= start`, with `contains(Instant)`, `overlaps(&TimeRange)` and `duration_seconds()`.
- `Clock` trait (`fn now(&self) -> Instant`), plus `FixedClock` (settable, advanceable) behind the cargo feature `testing`.
- `Id<T>`: a phantom-typed UUID with parse/format/serde, and a `define_id!` macro producing named aliases. This task defines `AccountId`, `RequestId`, `EventId`, `JobId`; later tasks add their own.
- `IdGen` trait (`fn new_id<T>(&self) -> Id<T>`, UUIDv7) and `TokenGen` trait (`fn token_256(&self) -> [u8; 32]`, `fn token_128(&self) -> [u8; 16]`). Deterministic `SeqIdGen` and `SeqTokenGen` behind `testing`.
- Real implementations `SystemClock`, `UuidV7Gen` and `OsTokenGen` in `kinevo-app` (`src/runtime.rs`), the only crate allowed to call the disallowed methods (with `#[allow(clippy::disallowed_methods)] // reason: composition root, CQ-07`).

**Out:**
- Time zones and calendar days (`jiff::tz`). The application layer adds them where needed (scheduler, execution).
- Database type mappings (`sqlx::Type`). `kinevo-db` adds those later behind its own feature, not here.

## Business rules

1. Ranges are half-open: `[09:00, 10:00)` and `[10:00, 11:00)` do not overlap (D-17).
2. Formatting is canonical: `2026-11-02T05:00:00Z` (no `.000`) and `2026-11-02T05:00:00.120Z` (contracts §1).
3. Parsing accepts `2026-11-02T12:00:00+07:00` and stores `2026-11-02T05:00:00Z`.

## Security

- S3 relevance: `TokenGen` produces secret material; the real implementation uses `OsRng` (SEC-23).
- No logging in this crate.

## Implementation notes

- Keep `kinevo-kernel` free of `std::time::SystemTime::now`. `jiff::Timestamp` construction from parts is fine.
- `FixedClock` uses an `AtomicI64` of milliseconds so it is `Sync` without locks.
- `SeqIdGen` must produce valid, increasing UUIDv7 values from a counter (fixed timestamp field plus counter in the random bits), so tests can assert ordering.
- Verify `cargo build -p kinevo-kernel --target wasm32-unknown-unknown` works if the target is installed. If it is not installed, mark this check `environment-limited` in the Report.
