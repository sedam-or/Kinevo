# T-003: Add the error-code registry and AppError to the kernel

## Goal

Every error a client can receive is a value of one Rust enum whose variants, HTTP statuses and retry classes match the spec registry exactly. A test fails as soon as the enum and `spec/standards/error-handling.md` diverge.

## Context

> **ERR-01** (`spec/standards/error-handling.md` §1): A code is added only in this registry (PR touches this file + the Rust enum + both catalogs); tests fail if any of the three diverge. *(This task checks spec ↔ enum; the catalogue check is added by T-016 when the catalogues exist.)*
> **ERR-02**: Retry class tells clients what to do: `never`, `after_change`, `backoff`, `reauth`.
> **ERR-03**: `details` is a JSON object whose keys are listed in the registry; `details` never contains S2/S3 values (only ids, counts, enums, numbers).
> **ERR-05**: Unmapped database errors become `internal_error` and log `unmapped_constraint` with the constraint name.
> **API-20** (`spec/07-api-conventions.md`): `code` is from the registry, owned by `kinevo-kernel`, stable forever.
> **API-21**: Validation failures return 422 with one `errors[]` entry per field, all failures at once.
> **Registry layout**: §2.1–§2.8 are tables `| \`code\` | HTTP | Retry | Title (EN) | details | Module |` with Retry letters N/C/B/R; §2.2 lists field-level codes (inside a 422 `validation_failed`); §2.9 lists process-level codes that never appear in API responses (`config_invalid`, `isolation_check_failed`, `migration_failed`, `unmapped_constraint`).
> **CQ-09**: Library crates use `thiserror` enums mapped to registry codes; `anyhow` only in `kinevo-app` startup and CLI glue. Errors are never stringly typed.

## Scope

**In:**
- `kinevo_kernel::errors::ErrorCode`: one variant per code in registry §2.1 and §2.3–§2.8, for **all** modules (the registry is closed and small, and later modules then need no kernel change). Each variant has `as_str()` (snake_case), `http_status() -> u16` and `retry() -> RetryClass`.
- `FieldCode`: one variant per field-level code in §2.2.
- `ProcessCode`: the §2.9 codes, kept as a separate type so they cannot reach an HTTP response.
- `AppError { code: ErrorCode, details: Details, errors: Vec<FieldError> }`, where `Details` is a small typed map of allowed value kinds (ids, integers, enums, string-lists of enum values). A `validation(errors)` constructor yields `validation_failed`.
- `FieldError { path: String, code: FieldCode, details: Details }`.
- A registry-sync test that reads `spec/standards/error-handling.md` from the repository (path relative to `CARGO_MANIFEST_DIR`) and asserts the set of codes, statuses and retry letters equals the enum.

**Out:**
- HTTP rendering (problem+json), localisation and catalogues: T-016.
- Database error mapping: T-010.

## Interfaces

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
pub enum ErrorCode { Unauthenticated, Forbidden, NotFound, ValidationFailed, /* … every registry code … */ }
impl ErrorCode {
    pub const ALL: &'static [ErrorCode];
    pub fn as_str(self) -> &'static str;
    pub fn http_status(self) -> u16;
    pub fn retry(self) -> RetryClass;
}
#[derive(Clone, Copy, Debug, PartialEq, Eq)] pub enum RetryClass { Never, AfterChange, Backoff, Reauth }
pub enum DetailValue { Int(i64), Str(&'static str) /* enum literal */, Id(uuid::Uuid), StrList(Vec<String>) /* enum values only */, Bool(bool) }
pub struct Details(/* BTreeMap<&'static str, DetailValue> */);
pub struct AppError { pub code: ErrorCode, pub details: Details, pub errors: Vec<FieldError> }
impl AppError {
    pub fn new(code: ErrorCode) -> Self;
    pub fn with_detail(self, key: &'static str, value: DetailValue) -> Self;
    pub fn validation(errors: Vec<FieldError>) -> Self;   // code = ValidationFailed, status 422
}
```

## Business rules

1. Every code's status and retry class come from the registry. They are never chosen at a call site.
2. `ErrorCode` never contains process-level codes (§2.9).
3. `validation_failed` carries all field errors at once (API-21).

## Security

- `Details` accepts no free-form strings, only enum literals, ids, numbers and lists of enum values. This makes ERR-03 (no S2/S3 in details) a type property.

## Implementation notes

- Parse the registry in the test with a simple regex over table rows (`^\| \`([a-z0-9_]+)\` \| (\d{3}) \| ([NCBR]) \|`) and the comma-separated code list in §2.2. Do not add a markdown parser dependency.
- The process-level codes in §2.9 are a backticked list. Assert they are *absent* from `ErrorCode::ALL`.
- `account_disabled` is 403 (the registry is authoritative).
